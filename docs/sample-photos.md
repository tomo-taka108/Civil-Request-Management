# サンプル現場写真の生成リスト

体験用サンプル案件（[SampleRequestSeeder](../database/seeders/SampleRequestSeeder.php)）に付ける現場写真を、AI で生成するための作業リスト（Issue #103）。

- 写真は **AI で生成**する（ChatGPT。上限に達したら Gemini）。フリー素材は再配布禁止の規約に触れるおそれがあり、実写は実在の場所・人物が写るため使わない（CLAUDE.md 6章）
- **優先度の高い順に作る。** どこで中断しても、デモ用アカウント（README 掲載）で見える範囲から埋まっているようにするため
- 案件の番号（`m01` など）は、データファイル内での並び順（`m`＝みどり／`t`＝つばき／`k`＝こはく）。例：`m01` は [sample_requests_midori.php](../database/seeders/data/sample_requests_midori.php) の1件目
- 写真の ID（`P01` など）は作る順番ではなく、写真を区別するための番号

| 優先度 | 事務所 | 見えるデモ用アカウント | 写真を付ける案件 | 新しく作る写真 |
|---|---|---|---|---|
| 1 | みどり・つばきの**一覧の先頭7件ずつ**（計14件） | staff101 / staff102 / staff201 | 14件 | 下記「最初に作る写真」の15枚 |
| 2 | みどりの残り | staff101 / staff102 | 12件 | 22枚 |
| 3 | つばきの残り | staff201 | 9件 | 14枚 |
| 4 | こはく（22件） | なし（README 非掲載） | 4件 | **作らない**（作った写真を使い回す） |

## 作り方

### 1. 最初に「共通の条件」を伝える

新しいチャットを開き、次の文をそのまま貼り付ける。以降の写真はすべてこの条件で作られる（チャットが長くなって条件が守られなくなったら、新しいチャットで貼り直す。Gemini に切り替えたときも最初に貼る）。

```text
これから、日本の地方都市にある土木事務所（道路・河川・砂防の維持管理）の業務記録用の写真を、1枚ずつ作ってもらいます。以下の条件はすべての写真に共通です。

- 写実的な写真。スマートフォンで撮影したような自然な写り。横長（4:3）
- 日本の地方都市・郊外の風景。実在の特定の場所ではない
- 日中の自然光（曇りまたは晴れ）。自然な色味で、ドラマチックにしすぎない
- 人物は写さない。車が写る場合はナンバープレートが見えない角度にする
- 看板・標識・路面表示などに、読める文字や数字を入れない
- 写真の中に日付・透かし・枠・キャプションを入れない

条件を理解したら「OK」とだけ返してください。
```

### 2. 1枚ずつ作る

各写真の「指示文」を貼り付けて生成する。

- **「補修後」などの写真（指示文が「〇〇と同じ場所で」で始まるもの）は、直前に作った写真と同じチャットで続けて頼む。** 同じ構図のまま状態だけ変えてくれるため、前後の写真がつながって見える
- 看板の文字が崩れている・日本では見かけない道路標示が混ざっている、など違和感があれば作り直す

### 3. 保存する

- 保存先：`database/seeders/photos/originals/`（Git には含めない設定にしてある）
- ファイル名：各写真の **ID の小文字＋拡張子**（例：`p01.png`）。拡張子は保存されたままでよい（png / webp / jpg）
- 作り終えたらチェックを付ける（`- [ ]` → `- [x]`）

### 4. 縮小して登録する

```bash
# originals/ の元画像を、横1280pxの JPEG（1枚300〜500KB）に縮小して database/seeders/photos/ に書き出す
docker compose exec php php database/seeders/photos/resize.php

# サンプル案件を入れ替えて、写真を付け直す
docker compose exec php php artisan sample:refresh
```

- 縮小した JPEG（`database/seeders/photos/p01.jpg` など）は Git で管理し、コードと一緒に本番へ届く。元画像（`originals/`）は Git に含めない
- どの写真をどこに付けるかは、サンプルのデータファイル（[database/seeders/data/](../database/seeders/data/)）に書く。受付時の写真は `'reception_photos' => ['p02']`、対応履歴の写真は履歴の3つ目の要素 `[1, '現地確認…', ['p01']]`
- 写真は投入先の環境の保存先（ローカルは `storage/app/private`、本番は S3）に保存される。本番での入れ替え手順は [運用手順書](operations-start-stop.md)「サンプルデータの入れ替え」
